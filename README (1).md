# Amalgam Round 1 – Polymer Property Prediction

## Project Overview

This project was developed for the **Amalgam Round 1 – Polymer Property Prediction** Kaggle competition. It uses polymer molecular structures represented as **SMILES strings** to predict two material properties:

- **Tg** – glass transition temperature
- **Egc** – electronic band gap

The competition evaluates predictions using the R² score for both targets, combined into one overall score.

## Dataset

The project uses the official competition files:

| File | Description |
|---|---|
| `train.csv` | Labeled training data |
| `test.csv` | Test data for which predictions must be generated |
| `sample_submission.csv` | Required submission format |

The training data contains the molecular SMILES representation, target value, and target type. The `target_type` column distinguishes `tg` from `egc`.

**Important:** Use only the official competition data and follow the competition rules. Do not add external datasets, labels, pretrained weights, embeddings, or precomputed model artifacts unless the competition rules explicitly permit them.

## Approach

The modeling workflow explores molecular feature engineering and machine-learning ensembles.

### 1. Molecular feature extraction

The experiments use RDKit to derive molecular representations, including:

- Molecular descriptors
- Morgan fingerprints at multiple radii
- MACCS fingerprints
- Polymer- and chemistry-related structural features

### 2. Model training

The notebooks experiment with models and combinations of models, including:

- LightGBM
- XGBoost
- CatBoost
- ExtraTrees / Random Forest
- Ridge-based models
- Similarity-based k-nearest-neighbor features

Separate prediction pipelines are used for Tg and Egc where appropriate.

### 3. Validation and ensembling

- Cross-validation and out-of-fold (OOF) predictions are used to compare experiments.
- Blending and stacking are explored to combine model predictions.
- Local validation scores are treated as estimates; the Kaggle leaderboard score is the external benchmark.
- New experiments should be compared against the strongest existing version before replacing it.

## Getting Started

### Option 1: Run on Kaggle (recommended)

1. Open the competition notebook environment.
2. Attach the official competition dataset.
3. Add the selected notebook to the Kaggle Notebook.
4. Confirm that the notebook uses the competition-provided input paths.
5. Run all notebook cells from beginning to end.
6. Check that the notebook generates the submission CSV.
7. Submit the generated CSV through the competition page.

Kaggle is recommended because the notebooks were designed around the competition dataset and its compute environment.

### Option 2: Run locally

Create a Python environment and install the libraries required by the notebook you choose. Common dependencies across the experiments include:

```bash
pip install numpy pandas scipy scikit-learn matplotlib seaborn jupyter
pip install rdkit lightgbm xgboost catboost optuna
```

Some experiments may use only a subset of these packages. Check the imports in the selected notebook and install any additional dependencies it requires.

Then start Jupyter:

```bash
jupyter notebook
```

Open the chosen `.ipynb` file, update the dataset paths if necessary, and run all cells.

## Reproducibility and Competition Compliance

For a reproducible experiment:

1. Run the complete notebook from a clean session.
2. Set and document random seeds.
3. Generate features, train models, infer on the test set, and create the submission inside the notebook.
4. Record the notebook version and the corresponding submission filename.
5. Follow all current competition rules, including restrictions on external data, artifacts, manual intervention, and team code sharing.

Refer to `polymer_competition_rules_and_modeling_brief.md` and the official Kaggle competition rules for the complete requirements.

## Notes

- A higher local OOF score does not guarantee a higher Kaggle score.
- Keep the strongest verified submission as a baseline.
- Change one major modeling idea at a time so experiments remain comparable.
- Treat planned experiments and expected score improvements as hypotheses until they are tested.
